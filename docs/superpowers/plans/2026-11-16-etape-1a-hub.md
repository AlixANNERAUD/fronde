# Étape 1a — Hub MCP : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un binaire `jarvis` qui expose en MCP (HTTP, jeton) la mémoire, l'agenda et les rappels CalDAV
d'un utilisateur, plus les outils d'autres serveurs MCP (MCPHub) derrière une recherche d'outils — utilisable
tout de suite depuis T3 Code et Claude Code.

**Architecture :** une crate bibliothèque `hub` (config, registre d'outils, recherche, mémoire, CalDAV, client
MCP amont, serveur MCP) et une crate binaire `jarvis` (CLI + axum). Tous les outils passent par un
`Registry` unique ; le serveur MCP n'est qu'une vue du registre. L'étape 1b (plan séparé) ajoutera Jarvis
(ACP → Claude Code) et le chat Leptos au-dessus de ce même registre.

**Tech Stack :** Rust stable (édition 2024), tokio, axum 0.8, rmcp 3.10, rusqlite 0.43 (bundled, FTS5),
reqwest 0.13, quick-xml 0.42, icalendar 0.17, chrono + chrono-tz, serde + toml, schemars, clap, tracing.

**Spec :** `docs/superpowers/specs/2026-11-16-jarvis-design.md` (§6.4, 6.5, 6.8, 6.9, 6.11, §7 étape 1).

**Hors de ce plan :** déclenchement des rappels et notifications (1b, avec la web app), récurrences,
rechargement à chaud de la config, édition par l'interface, multi-utilisateur, ACP, Leptos.

## Global Constraints

- Principe directeur : le plus simple possible ; un mécanisme n'entre que si son absence fait mal.
- Versions **épinglées exactement** (`=`) pour `rmcp` ; les autres en `^` sur les versions ci-dessus.
- Code, config et noms d'outils **en anglais** (publication) [Claude] ; les messages d'erreur d'outil aussi.
  Les préfixes de la spec deviennent : `memory_`, `calendar_`, `reminders_`, `search_tools`, `use_tool`.
- Noms d'outils : `^[a-z][a-z0-9_]{0,63}$` (l'API Claude refuse les points et > 64 caractères).
- Descriptions d'outils télégraphiques et impératives ; une erreur dit toujours comment corriger.
- Résultat d'outil = texte JSON `{"result": <valeur>, "next": "<conseil>"?}` ; erreur = `isError: true` +
  `{"error": "<quoi et comment corriger>"}`.
- Config : un seul TOML, `deny_unknown_fields` partout ; secrets jamais en clair dans le TOML, seulement
  `{ file = "…" }` ou `{ env = "…" }`.
- Rien de ce qui vient d'une source externe n'est mémorisé automatiquement (garanti par le guide, §Task 10).
- Le hub démarre même si un serveur amont ou CalDAV est injoignable.
- Pas d'attribution IA dans les commits ; messages de commit en français, impératif.

## Review Focus

1. **Événements créés sur un téléphone** (TZID Europe/Paris, journée entière en `DATE`, heure flottante) :
   affichés à la bonne heure locale → test `parses_tzid_allday_and_floating` (Task 6).
2. **MCPHub éteint au démarrage ou qui tombe** : le hub démarre, ses outils renvoient une erreur claire, et il
   se reconnecte → tests `upstream_down_at_start_retries` et `call_after_disconnect_explains` (Task 9).
3. **Fichiers mémoire édités à la main** (absents, `\r\n`, très longs) : relus et réindexés au démarrage →
   test `reindexes_hand_edited_files` (Task 5).
4. **Requête de recherche avec caractères FTS5** (`"`, `-`, `:`, `*`, `(`) ou accents → jamais d'erreur SQL →
   tests `search_survives_fts_syntax` et `search_ignores_accents` (Task 3).
5. **Deux agents écrivent la mémoire en même temps** : pas d'écriture perdue, plafond respecté →
   test `concurrent_adds_respect_cap` (Task 4). Le plafond se compte en caractères, pas en octets.
