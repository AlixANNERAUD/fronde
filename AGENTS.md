# AGENTS.md

fronde (code name) is a personal agent hub written in Rust: it drives coding agents through their
own subscriptions over ACP, serves its memory and tools (a calendar component among them) over MCP,
and offers a web chat.

## Layout

| Crate | Role |
| --- | --- |
| `crates/hub` (`fronde-hub`) | Tools registry (`tools.rs`; a call carries a `CallContext`: who calls, a thread's agent (`Caller::Thread`) with its thread's stream and running turn or an outside MCP client by its `clientInfo` name (stream `conversation`), for which user and stream (`secret_scope` gives the ephemeral secrets it may use: its stream, its caller id), and the token rmcp cancels when the caller gives the call up (rmcp never stops the handler, so a tool that waits watches it), passed on by `use_tool`; returns a `secret_ref` or the stored name, never the value; served only when the `Requests` keep secrets), served only with the chat's `Requests`, the prefix `user_` reserved, its texts capped and free of hidden characters (`fronde_protocol::text`), an outside client named like Fronde or the assistant refused) and search (`search.rs`: FTS5 in an in-memory SQLite, rebuilt at the first search after the tools changed), memory (its full-text index is `fronde.db`'s `memory_fts`), upstream MCP servers (`upstream.rs`: tools through rmcp's `call_tool`, which hands an `input_required` round to the same handler as a server's `elicitation/create`; `UpstreamClient` advertises form elicitation only with the chat's requests (`Asking`) and shows each form as a card for the admin, `Caller::Source`, `admin_only`, `tied`, through `fronde_requests::elicitation`, only while a call to that server is in flight and one card at a time per server (`Calls`: the calls in flight, by whom, a thread agent's turn and stream; the card's `during`; the card closed when the last call ends, and with the turn when one thread's agent alone calls; refusals warned at most once a minute per server), asked and awaited in a task of its own, cancelled when the server cancels or the call is dropped; a form it cannot show or that looks like a secret declined with `_meta` `fronde/refused`, a URL form cancelled; a call its caller gives up is dropped upstream; the source names `fronde` and `assistant` are reserved), the MCP server; `source.rs` is where tools come from: the `ToolSource` trait and the one supervisor that starts every source (the hub's own tools, upstream servers, components), registers its tools and restarts it with backoff (a component that fails to start is given up, unless its error is a `Waiting`, such as a stored secret not set yet, which is retried with one growing backoff until it starts or fails otherwise, and is then given up); | `crates/fs` (`fronde-fs`) | Private-file helpers shared by the hub and the database (`fronde-db`): 0700 directories, 0600 files, durable atomic replacement (`atomic-write-file`: sync of file and directory) |
| `crates/db` (`fronde-db`) | The database, one SQLite file `<data>/fronde.db` through SeaORM: `open` (created 0600, WAL, `synchronous = FULL`, pending migrations applied in one transaction), `open_read_only` (`fronde check`: no migration, no write), `begin_write` (`BEGIN IMMEDIATE`, for every transaction that writes), `kv` (values by scope and key, optionally expiring), `approvals` (component approvals by source and both hashes, read by `fronde_wasm::Checks::load`), `ephemeral` (`EphemeralSecrets`: secrets in memory only, behind an `sr_` reference that works for its conversation (any turn of it, by design) and asker, once by default, 1 h by default and 24 h at most, every refusal the same `RefError`; the key check in `kv` `secrets`/`key_check`, written with the first secret, sealed under its own domain label, an older check sealed again by the next write), `master_key` (`MasterKey`, format `fronde-key-v1:<base64url>`, kept by a `Backend`: `systemd` (`systemd.rs`, `$CREDENTIALS_DIRECTORY/fronde-master-key`, read only), `keychain` (`keychain.rs`, keyring-core with one store crate per platform, Secret Service over zbus with RustCrypto on Linux, entry `fronde` / `master-key@<hash of the data dir>` for a first key, then the entry's user recorded in `kv` `secrets`/`keychain_entry` with the first secret, each call on a blocking thread under a 2 s timeout that covers waiting for the one call in flight per keychain (the thread keeps that slot until it ends, so a call stuck behind an unlock prompt never starts another), a keychain that is locked or does not answer an error, one absent or unreachable the only kind `auto` falls through to the file; absent when `FRONDE_KEYCHAIN=off` (its error names the variable; `serve` and `secret set` warn at start), which `mise.toml` and `.cargo/config.toml` set so that no test or development run, nor a bare `cargo test`, reaches the machine's keychain; `migrate` moves a key an earlier version left in `<data>/master.key`, `locate` finds it without moving for `fronde check`); `Backends` (`backends.rs`, built by `Config::master_key_backends` from `[secrets] backend`) picks one: a named one alone (refused while secrets are stored if it is not the recorded one), or `auto`: the backend recorded in `kv` `secrets`/`backend` (written by `secrets::set` with the key check, and by `upgrade_key_check` at start), else for the first key the systemd credential, then the keychain if it answers, then the file; never falls through once recorded or while anything is sealed; created only while nothing is sealed, never from the environment; `load` asks no backend while nothing is sealed; a key is made under `KeyLock`, an exclusive lock on `<data>/master-key.lock` across processes, held by `secrets::store` until the first secret is sealed, and kept by a timed-out keychain call's thread; `rotation.rs`: `rotate` (kv `secrets`/`rotation` marker, new key in the backend's next slot `master.key.next` or entry `<user>.next`, read back, `secrets::reseal` of every row and the key check in one transaction, then the current slot replaced, the next slot and marker removed), `move_to` (same key copied, read back, checked and recorded by `upgrade_key_check`, then removed from the old backend; never replaces another key, never writes systemd), `finish` (at `serve` start and before both: the key that opens the key check becomes or stays current, warned), `rotate_crashing_after`/`move_crashing_after` behind `testing`), `running` (`claim`: an exclusive lock on `<data>/fronde.lock` holding the pid and command, taken by `serve` for its lifetime and by `fronde secret rotate-key`/`move-key`, whose error names the holder) |
| `crates/migration` (`fronde-migration`) | The schema's migrations (sea-orm-migration), one per change, never edited once pushed; `examples/migrate.rs` applies them to a SQLite URL for `mise run entities` |
| `crates/entity` (`fronde-entity`) | The SeaORM entities, generated from the migrated schema by `mise run entities`, never edited by hand |
| `crates/protocol` (`fronde-protocol`) | Types shared by the conversation log, the server and the web interface (`Event`, `Entry`, `ThreadId`); `request.rs` what a request's card shows (`Card`: `Permission`, `Form`, `Secret`; `Field`: `Choice`, `Text` (with a `TextFormat`), `Number`, `Toggle`, at most `MAX_FIELDS` to a form; `Card::check`, every text's cap, no hidden character and at most `MAX_CARD_BYTES` (64 KiB) as JSON, which `Requests::ask` runs on every card; a server's form says whose calls it served, `CallBy`), what the page answers (`Response`, a form's values a `FieldValue` each, whose JSON is an object for a choice, a string, a number or a boolean), how it ended (`Outcome`), and `check`, the rules an answer follows (formats, lengths, bounds), run by the page before sending and by the server; a secret card (`Card::Secret`) is answered with a `SecretValue`, which prints `[REDACTED]` and is zeroed when dropped; `text.rs` which characters a card never shows (`hidden`: controls, format, separators, private use, unassigned, default-ignorable code points, by `unicode-properties`) and how a text from elsewhere is cleaned for a card (`line`, `block`: hidden characters replaced, head and tail kept around a marker, `Notes` saying so); serde, serde_json, chrono, zeroize and unicode-properties only |
| `crates/requests` (`fronde-requests`) | Requests to the user: the `requests` table, written before its card is shown by a `Journal` (the threads, each request in its topic's thread, told the `Caller`: `Caller::Thread(id)`, stored `thread:<id>`, a row from before threads (`assistant`) read as thread 1's, any other unknown stored caller `Caller::Unknown`, never trusted: cancelled at open, never answered, owning no secret; an outside asker is named on the card, an upstream server marked `server`), answered once through `Requests::answer` (identity, then the card's rules, then a compare-and-set on `pending`, then the journal, then the waiting asker), cancelled, or expired by a timer of its own (its `Waiter` also gives up at the expiry plus a grace, should the database fail to close it); a retry by `client_request_id` joins only a request asking the very same thing that is still current (`retries`: a thread's agent's same turn, an outside client's pending request or its timeout), else a new request, or `Reused` while another pending request holds the id (unique among pending rows only); `ask` refuses a card that fails `Card::check` and a permission from anyone but a thread's agent, and a card it cannot show is cancelled without a close shown for it; `answer` logs a refusal as a warning, never the answer; `open` expires overdue rows, pending permissions, `tied` forms (kind `elicitation`: the agents' and servers' elicitations) and any `source:` caller's (the call that waited is gone, and their answer must never reach an agent; retried at once by a timer if that fails), announces rows a crash left unshown and cancels a row it cannot read; a secret answer goes to its `SecretStore` (`open_with`: the ephemeral store, or sealed with the master key from `Backends`, the latter for an admin only) under one lock, before the compare-and-set, and its row and asker get only where it went (`Saved`); a form declined unseen with the plain `SECRET_REFUSAL` when its message or the name, title or description of anything typed reads like a secret, `looks_secret`: NFKC, case folding, digits read as letters, the `unicode-security` confusable skeleton, invisible characters ignored, then `SECRET_WORDS` and `SECRET_PHRASES`, and `NAME_WORDS` (`code`, `pin`, `key`) only in a field's own name or title, `names_secret`; toggles start off, a `uri` default kept only for http(s), a lone plain choice required; `Refused` with a `reason` for the asker and a `detail` for the log), with `DEFAULT_TIMEOUT` (10 min) and `MAX_TIMEOUT` (1 h) |

Components are built by `mise run components`, which builds each project listed in
`$FRONDE_COMPONENTS` and copies the `.wasm` files to `components/dist`, each with its manifest
beside it as `<name>.toml` (mr-boxington prunes idle target directories); the container image
ships them in `/app/components`; `fronde-wasm`'s tests load them from there, and `mise run test` builds them
first. Likewise `mise run python` fetches the Python runtime into `python/`, which the image ships in
`/app/python` and the tests load (`FRONDE_PYTHON_DIR` overrides it). `mise run build` builds them before the binary, which approves exactly those files. A component may not import `wasi:filesystem` or `wasi:sockets`. The SDK's `bindings` module
is the only place allowed `unsafe` code (the generated glue needs it); components forbid it.

The server has no Dioxus dependency: it serves the built interface as static files from
`FRONDE_SITE_ROOT` (default `target/dx/fronde-web/release/web/public`, written by
`mise run web-build`). In development, `mise run web-dev` serves the pages itself and proxies
`/ws` and `/auth` to `mise run dev` (`crates/web/Dioxus.toml`): keep every backend-only route
under one of those.

Server-side Cargo commands leave out `fronde-web` (`$FRONDE_SERVER_PACKAGES`), whose
dependencies are wasm-only. Lint and tests run it on its own, natively and for wasm32. It embeds
`crates/web/assets/tailwind.css` at compile time: the hidden `web-css` task generates it from
`crates/web/style/tailwind.css` with mise's Tailwind, and `lint`, `test`, `web-build` and
`web-dev` run it first.

## Commands

Everything goes through [mise](https://mise.jdx.dev), which pins the toolchain and routes Cargo
through mr-boxington.

| Command | Does |
| --- | --- |
| `mise install` | Installs the pinned tools |
| `mise run format` | Formats the code, components included |
| `mise run lint` | rustfmt check and clippy with `-D warnings`, on the server code, the web interface (native and wasm32) and the components (wasm32-wasip2) |
| `mise run components` | Release build of the components for wasm32-wasip2 into `components/dist` |
| `mise run python` | Fetches the pinned CPython WASI build (and tzdata) into `python/`, checks its hashes and byte-compiles the stdlib |
| `mise run test` | The test suite (nextest), after `components` and `python` |
| `mise run agent` | Installs the locked Claude ACP adapter (`agent/package-lock.json`) into `agent/node_modules`; Node.js comes from mise, which puts the adapter on `PATH` |
| `mise run deny` | cargo-deny: advisories, licences, bans, sources, for the root workspace and the components |
| `mise run check` | What CI runs: lint, tests, cargo-deny |
| `mise run dev` | The server on http://127.0.0.1:8484 for `web-dev` (password `fronde`; config and data in `target/dev`) |
| `mise run web-dev` | The Dioxus interface with hot reload on http://127.0.0.1:8080 (dx serve); `/ws` and `/auth` go to `mise run dev` |
| `mise run web-build` | Release build of the Dioxus interface into `target/dx/fronde-web/release/web/public` |
| `mise run build` | Release build: `web-build`, `components` and `python`, then `target/release/fronde` |
| `mise run docs` | Builds the user guide (mdBook, `docs/`) into `docs/book` |
| `mise run entities` | Regenerates `crates/entity` from the migrations with `sea-orm-cli` |

Builds are heavy: run one cargo command at a time, through `mise exec -- cargo …` or a mise task.

`crates/server/tests/live.rs` chats with the real Claude adapter on the owner's subscription. It
is ignored and runs only by hand, with `CLAUDE_CODE_OAUTH_TOKEN` set (the agent has a fresh home there) and `FRONDE_LIVE_AGENT` set to the adapter's path (`agent/node_modules/.bin/claude-agent-acp`, after `mise run agent`):
`mise exec -- cargo nextest run -p fronde --test live --run-ignored only --no-capture`.

## Dioxus 0.7 usage

Pinned in `Cargo.toml`; `crates/web` is the app, `crates/client` its framework-free model.

- `rsx!` with `#[component]` functions; lists use `for` with a stable `key` (generation and seq,
  never the row version, which would remount the node on each chunk).
- Shared state is `Signal`s; the WebSocket lives in one `use_coroutine` (`socket.rs`) that owns the
  socket and the retry timer. Connection logic stays in `fronde-client`, native and tested.
- Components and pages take plain props (no context needed to render) so `dioxus-ssr` and
  VirtualDom tests drive them natively.
- Browser-only code (sockets, timers, `web_sys`) sits behind `cfg(target_arch = "wasm32")`, with a
  native stub for tests.
- Vendored rust-ui components keep upstream classes; changes carry a `// fronde:` marker.
- Tailwind is built by `mise run web-css`, not by `dx`; `dx` only bundles the wasm.
- Dev: `mise run web-dev` for the UI (proxies `/ws` and `/auth` to the backend), plus `mise run dev` for the backend
  in another terminal. Release: `mise run web-build`.

## Rules

- Keep it as simple as possible: add a mechanism only when its absence hurts.
- Integrations with outside services (a REST API, CalDAV, any standard) are components, not
  hub code; an upstream MCP server is used as it is when a good one exists. Native Rust is for
  the core: memory, scheduling, the hub itself. Every source of tools is a `ToolSource` under the
  supervisor, configured as a `[[sources]]` entry.
- Components are independent projects that will move to their own repositories: each has its own
  `Cargo.toml`, `Cargo.lock` and release profile, and depends only on `fronde-component` and
  external crates, never on another Fronde crate. The SDK depends on no Fronde crate either.
- A released WIT directory (`wit/v0.1`, …) is frozen: never edit it, not even to add a function or
  an enum case. A change is a new directory with its own host module (`crates/wasm/src/v0_2/`),
  and the host keeps serving the earlier versions.
- Tool names match `^[a-z][a-z0-9_]{0,63}$`; tool descriptions are short imperative rules; a tool
  error always says how to fix it. A component's tools start with a prefix of its manifest's
  `tool_prefixes`, which no other source uses.
- Durable structured state lives in the one database, `fronde.db`, through SeaORM; raw SQL only
  for FTS5. A schema change is a new migration, never an edit of a pushed one, followed by
  `mise run entities`: entities are generated, never edited by hand.
  The bundled SQLite is held at `libsqlite3-sys` 0.37 by sqlx-sqlite, so `deny.toml` ignores
  RUSTSEC-2026-0459: drop that ignore as soon as a sqlx release accepts 0.39.
  It also ignores the zbus 5 sub-crates flagged unmaintained (RUSTSEC-2026-0370 to 0372), which
  keyring-core's Secret Service store brings: oo7 0.7 is on zbus 6, but no keyring-core store uses
  it yet. Revisit by 2027-03.
- Secrets never appear in the configuration file, logs or tool output: `{ file = "…" }` or
  `{ env = "…" }` only, or `{ stored = "…" }` (sealed in `fronde.db`) for a component's
  credential.
- Resolved secrets are `secrecy` types. `expose_secret` is called only at the sites listed, with
  their count per file, in `crates/server/tests/secrets.rs` (`expose_secret_call_sites`); a new use
  is added to that list on purpose, and reviewed.
- Nothing read from an external source (web, email, document) is saved to memory automatically.
- Never lose calendar data the tools do not model: edits keep every component, property and
  parameter they do not change; only formatting (folding, parameter order, quoting, a text value's
  transfer encoding) may change. The calendar uses the owner's calcard fork, which keeps values
  as read: fix a loss there, not with a workaround in the component.
- Tests never touch a real calendar, model or MCP server: use `wiremock`, in-process fakes and
  temporary directories.
- Rust/UI components are vendored by hand in `crates/web/src/components/ui/`, with
  `crates/web/src/components/LICENSE-rust-ui` (MIT) beside them: keep their classes and
  structure, and mark any change to them in place with a `// fronde:` comment. Icons are Lucide's
  (ISC, `crates/web/src/components/LICENSE-lucide`), drawn inline in
  `crates/web/src/components/icons.rs`; add one there from Lucide's paths rather than adding an
  icon crate.
- Comments explain why, never restate the code. Docs are plain, concise English with no em dashes.
- The user guide in `docs/src` follows Diátaxis (tutorials, how-to guides, reference, explanation).
  A change to settings, endpoints, tools or behaviour updates the matching pages in the same commit.
- Work and push directly on `main`. Commits follow Conventional Commits (`feat:`, `fix:`, `test:`,
  `build:`, `ci:`, `docs:`, `chore:`), imperative, in English. Do not mention AI tools and add no
  `Co-Authored-By` or "Generated with" lines.
- Working notes (`docs/superpowers/`) stay local and are never committed.
